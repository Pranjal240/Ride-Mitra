## 1. Product Overview

**Ride Mitra** is a **university-exclusive carpooling platform** for **J.C. Bose University of Science & Technology, YMCA (Faridabad)**. It connects students and staff who travel the same routes so they can share rides — cutting cost, traffic, and the daily wait for transport. It is **not** a public ride-hailing clone; it is a closed, trust-first campus mobility network governed by the university (via a single admin).

**This PRD covers the website only** (the existing repo). The mobile app is specified separately in `APP_PRD.md`; both share one Supabase backend and one design system.

### 1.1 Goal of this rebuild
Transform the current UI from **inline-style, card-and-text-heavy pages ("AI slop")** into a **single, coherent, motion-rich, editorial product** built on a design system generated by the `ui-ux-pro-max` skill, with a curated component library (6 provided components) woven in consistently, and true **route/direction-based carpool matching**.

### 1.2 Success definition
- One design system, applied everywhere (no per-page inline color/spacing improvisation).
- The 6 provided components are the backbone of inputs, galleries, scroll reveals, and the intro-video experience — used site-wide, not one-off.
- Carpool matching reflects the real rule: **a ride only appears if a registered driver's route travels in the same direction along the rider's corridor** — not just "endpoints within 10 km."
- Fully responsive (desktop hover experiences + mobile vertical experiences), accessible (WCAG AA), and fast.

## 3. Design System Directive

**Do not hand-pick colors.** The build must start by running the `ui-ux-pro-max` skill to generate and persist one design system:

```bash
python3 .claude/skills/ui-ux-pro-max/scripts/search.py \
  "university campus carpooling ride-share community trust-first mobility" \
  --design-system --persist -p "Ride Mitra"
```

This produces `design-system/MASTER.md` (+ `design-system/pages/` overrides). All pages build to `MASTER.md`; page-specific deviations go in `design-system/pages/<page>.md`. The three legacy palettes (navy+gold, blue+beige, purple+neon) are **retired** — MASTER.md is the single source of truth.

### 3.1 Token reconciliation (required to make provided components compile)
The provided components reference **shadcn-style semantic tokens** (`bg-muted`, `bg-muted2`, `outline-muted3`, `bg-primary`, `text-foreground`, `bg-background`) and `cn` from `@/lib/utils`. The build must:
1. Create `src/lib/utils.ts` exporting `cn` = `twMerge(clsx(...))` (add `clsx` + `tailwind-merge`).
2. Define those semantic tokens in the Tailwind v4 `@theme` block of `src/index.css`, **mapped to the `ui-ux-pro-max` palette** (light + dark). This replaces the ad-hoc `theme.ts` inline usage over time.

## 6. Feature Requirements (web)

All features are **admin-managed** by the university. Requirements marked **NEW** don't exist yet.

### 6.1 Identity & roles
- Google OAuth sign-in, scoped to the JCBUST community.
- Roles: `student` (rider), `driver`, `both`, `admin`, `pending_admin`.
- **NEW — Hardcoded sole admin:** `pranjalmishra2409@gmail.com` is the **only** admin. Add a client constant (replacing reliance on `VITE_ADMIN_EMAILS`) **AND enforce server-side** via Supabase **RLS policies / edge-function checks** — client gating alone is not security. Any other user selecting "admin" becomes `pending_admin` and is never elevated.

### 6.2 Ride discovery — corridor/direction matching (**NEW**, replaces 10 km endpoint radius)
- Rider enters **current location + destination**.
- A ride matches only when the **driver's registered route travels the same corridor and direction**:
  - Rider's pickup is within a small threshold (e.g. ≤1.5 km) of the driver's route **polyline** (point-to-polyline distance), AND
  - Rider's drop is likewise near the polyline, AND
  - The drop appears **after** the pickup along the route (direction/bearing check — not going backwards).
- Reuse `route_polyline` on `rides` and the polyline decoder in `src/lib/maps.ts`. Keep date/time filtering and past-ride cleanup (`cleanupPastRides`).
- Results show the driver's **vehicle type** (car/bike/scooty/…), **seats available**, **price per seat**, rating, and ETA.

### 6.3 Offering a ride (driver)
- Driver registers vehicle type + number + docs (existing `driver_verification`), route (with polyline), schedule, seats, and **price per seat**.
- **Capped pricing freedom (NEW):** driver sets price freely **within a university-defined min/max band** (derived from distance; enforce bounds in UI and server-side). Show the allowed range inline.

### 6.4 Booking, bargaining, payments
- Seat selection → booking request → driver accept/decline.
- **NEW — Bargaining:** rider may propose a counter-price within the allowed band; driver accepts/counters; agreed price flows into the booking. Persist offers (new lightweight table or `messages` metadata) and audit them.
- **Razorpay** payment (INR) on confirmation. **Fix the env-name bug** (standardize on one of `VITE_RAZORPAY_KEY_ID`, declare it in `vite-env.d.ts`, read the same everywhere).

### 6.5 Live map, tracking & safety
- Dynamic route **polylines** + live **distance/ETA** (Mappls/ORS) — not just markers.
- Live GPS tracking (`live_locations` + Supabase Realtime) on `/tracking/:rideId`.
- **SOS + emergency connect:** SOS injects real `lat/lng` into the `send-sos` edge function payload so the contact gets a clickable maps link. Keep SOS always reachable.
- **NEW — Live VC support:** in-ride/support **video call** via **WebRTC**, using **Supabase Realtime as the signaling channel** (offer/answer/ICE over a channel). Falls back to the existing text chat. (Server: add a `signaling` channel; optionally a TURN server config.)

### 6.6 Admin console
- `/admin` for the sole admin only: analytics/dev metrics (`admin_analytics`), user/driver moderation, ride management, SOS command center, reports, support threads, announcements, audit logs. Rebuild visuals to the design system; keep data contracts.

### 6.7 Explicitly out of scope
- **Uber API** — discarded (no public carpool-matching API; Rides API deprecated/partner-only). At most, an **optional** "compare with typical cab fare" reference in the pricing UI if a usable estimate is available; otherwise omit entirely.

## 8. Non-Functional Requirements
- **Responsive & mobile-first:** desktop hover experiences (HoverExpand_001) degrade to mobile vertical/press (HoverExpand_002); no horizontal page scroll; touch targets ≥44px.
- **Accessibility:** WCAG AA contrast (verify in light + dark), visible focus rings (SmoothInput hides native caret — ensure the animated caret + focus outline remain visible), keyboard nav, `prefers-reduced-motion` respected by all Skiper animations, alt text, aria-labels on icon buttons.
- **Performance:** motion 150–300ms; animate transform/opacity only; lazy-load below-fold + heavy media (maps, video); reserve space (no CLS); code-split routes; WebP/AVIF images.
- **Consistency:** SVG icons only (no emoji as icons); one icon family; semantic tokens (no raw hex in components).
